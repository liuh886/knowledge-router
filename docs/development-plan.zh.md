# 开发计划（基础数据与证据服务）

这份文档是 KnowledgeRouter 的**开发计划与接手说明**。它记录：现在到了哪一步、哪些决定已经定下、
剩余交付项各自要达到什么、以及下一轮如何继续。它面向两类读者——继续开发的 agent，以及决定优先级的人。

与其他文档的分工：

| 文档 | 作用 |
|---|---|
| 本文 | 计划、决策、验收条件、接手顺序 |
| `TASKS.md` | 逐项勾选的实现清单与历史记录 |
| `EVALUATE.md` | 已实际验证过的质量结论（按日期追加） |
| `docs/*review*.zh.md` | 独立复核记录，含当时复现的缺陷 |
| `docs/context-base-landscape-and-roadmap-2026-09-22.zh.md` | 同类产品调研与方向论证 |

本文不重复论证方向，只承载"接下来做什么、做到什么算完成"。**计划变更应先改本文**，再落到 `TASKS.md`。

## 2026-10-25 基础数据层收敛（当前执行计划）

用户已确认优先治理 zhihaol 基础数据，研究综合和应用决策交给调用方。本节覆盖下方 KR-N1–N5 的执行顺序；旧计划及已实现能力保留，不删除历史、不自动变更已登记 Context、写入策略或来源内容。

产品边界和数据语义以 [基础数据契约](data-layer-contract.zh.md) 为准。Context 是可选的资料选择视图，不是数据访问的前置条件。`research:ccs` 留作兼容配置，CCS 主张更新、冲突解释和知识页发布退出本轮核心验收；个人记录和领域 schema 继续有效。现有知识页/编译卡片仍可显式使用，不因方向调整被自动删除或认证。

| 顺序 | 工作包 | 交付与验收 |
| --- | --- | --- |
| 1 | DL-1 数据契约与只读基线 | 身份、角色、来源、时间、引用、版本关系的语义；可重跑盘点和原始证据；缺失字段不自动视为缺陷；完成性、截断和并发变化分开披露 |
| 2 | DL-2 解析与治理信号正确性 | 先修已复现的链接误报；报告保留规则版本和来源依据；不同规则/范围的计数不得当作治理效果直接比较 |
| 3 | DL-3 三类数据小样本 | 原始捕获、普通知识笔记、应用对象记录各选少量样本，逐项检查身份/引用/完整性；保留领域 ID 与 schema，未知不猜测，不批量补字段或改 ID |
| 4 | DL-4 受控修订与复核 | 对确证问题生成精确修改与原始哈希；只通过既有 broker 能力执行获准操作；策略不允许时保留可审阅草稿，不绕过 broker；写后按同一规则复核 |

DL-1–DL-3 可以先做只读和隔离验证，不以发布机制为前置。KR-N1 的运行版隔离仍是重要工程待办；任何新的生产写入功能或宿主激活在受测运行边界明确后推进。KR-N2 改为来源读取/引用/未知披露验收，KR-N3 保留数据完整性和新鲜度部分；研究判断、业务优先级与复盘策略不下沉到内核。KR-N4 转为可选研究应用试点；KR-N5 保留为后续只读适配器，不是当前数据治理的前置。

完成状态写入 TASKS，实际测试写入 EVALUATE。私有全量清单与恢复材料存放 Vault 外；库内只通过 broker 建立一份人可读治理入口，其余文档引用它或相应代码契约，避免多份事实清单独立维护。

2026-10-26 第二轮按 DL-2/DL-4 推进：修复 quality 队列筛选归属，按同一来源快照的完整链接出现记录判定聚合问题，不能只看首个路径或截断样本；范围内无法读取所需标签时明确归属不完整。随后对缺失图像执行限定路径/备份成员名查找，对身份重复做消费者与快照关系核对；找不到不补造，保留 ID 和原始副本。结果追加到既有治理入口，经 broker 保留旧前缀，不另建独立事实清单。

## 2026-10-25 下一轮执行计划（被上节替代，历史依据）

本节是接下来工作的当前优先级，覆盖下方历史批次的接手顺序。依据：[完成度诊断](completion-diagnosis-2026-10-25.zh.md)。当前处于“计划完成、实现待开始”；本轮只更新计划，不切换运行版本或改写知识内容。

维护审计入口：[2026-10-25 技术债与规则治理](maintenance-audit-2026-10-25.zh.md)。后续追加的维护操作和验证以该记录及 `EVALUATE.md` 为准；这里的“本轮只更新计划”描述制定计划时的操作边界。

**文档时效与接手规则：** 下方 2026-10-23 批次及第 1–9 节保留历史依据，其中的“当前”、待决定项、测试数和验收数字均属于当时快照。不得要求今天的结果与旧数字一致。接手先读本节和最新 `EVALUATE.md`，再运行只读状态检查；实现顺序以 KR-N1–N5 为准。440 项测试是 2026-10-25 的已测基线，不是固定数量门槛。第 7 节的全文编辑问题已由 ADR-001 决定，第 7 节的零维护策略结论已被后续个人 Context 登记取代。运行维护命令成功也不代表 KR-N3 的全部产品验收已完成。

核心目标：交付一个可回退、能被 Agent 有效使用、能完成真实知识更新的本机版本。核心批次为 KR-N1 至 KR-N4，估计 5–9 个集中工作会话；宿主联调和证据复核可能影响估时。每包验收后再进入下一包，失败则在该包修复，不以加功能替代验收。

| 顺序 | 工作包 | 估计 | 前置 | 主要交付 |
| --- | --- | --- | --- | --- |
| 1 | KR-N1 运行版本收口 | 1–2 会话 | 无 | 明确发布版本、不可变运行快照、指纹与可验证回退 |
| 2 | KR-N2 Agent 真实任务验收 | 1–2 会话 | KR-N1 | 非空来源在真实新会话中被注入并引用，异常路径可观察 |
| 3 | KR-N3 维护与新鲜度闭环 | 1–2 会话 | KR-N2 | 一次完整维护基线、明确刷新策略、每次少量有价值的复盘动作 |
| 4 | KR-N4 一个知识更新试点 | 2–3 会话 | KR-N3 | CCS 知识页受控更新为下一版，下一真实会话使用该版本 |
| 第二批 | KR-N5 Ownly 按需只读接入 | 1–2 会话 | KR-N1、现有 MCP 可连接 | 对象/历史/订阅事实的薄适配；沿用已批准的里程碑 G |

**KR-N1：先让“运行版”可识别、可回退。**

实施范围：

- 审阅当前工作树，区分已有修复、本轮变化和其他未关联修改，形成可重建、可审阅的源码基线；不重置、丢弃或混入无关修改。
- 保留仓库为唯一编辑主源，以当前 440 项验收对应的完整代码为首个可回退基线，构建带版本号与 SHA-256 manifest 的本机不可变发布快照；不能直接用缺少当前入口的旧 tag 冒充兼容回退。快照是派生产物，禁止直接维护另一份源码。
- 通过一个本机发布工具完成构建、校验、启用和回退。源码位置与运行位置分离；稳定 CLI、PowerShell、Ductor bridge 使用同一活动版本，运行代码与操作契约同版。
- 状态输出显示实际运行版本、路径和指纹。保持 Vault、外部状态目录和写入策略不变。仅更换每次调用会加载的 Router 运行快照；宿主进程自身升级另行记录，不顺带重启。

交付物：发布/激活工具、活动版本描述、已测发布快照、回退操作说明和验收记录。

通过条件：现有完整回归与新增发布测试通过；在隔离用例中修改源码不影响已启用运行版；CLI/PowerShell/bridge 报告同一指纹；切回前一已知可用版本并通过只读检索，再切回新版本；启用失败不会留下半切换状态。原始记录、策略与持久控制记录哈希不受切换影响。

**KR-N2：证明 Agent 实际使用了知识。**

实施范围：

- 选 3 个在 Vault 中确有依据的真实问题，先冻结预期来源与允许回答范围：个人成果证据/核验状态、投资记录的来源与待核实情况、一个研究主题问题。这里验证引用与未知披露，不代替事实核验或投资判断。
- 走真实新会话的编排与模型调用路径，确认非空检索结果在模型调用前注入、答案引用正确路径/行号，并保留 pending/stale/未知信息。
- 在隔离用例验证：续接会话不重复自动检索、无相关资料时明确缺证据、入口不可用/超时时区分失败与空结果、来源变化时披露过期。不会为测试向外部联系人发送消息。
- 增加必要的最小诊断字段：会话关联 ID、调用路径、命中数、耗时、结果状态与注入标记；默认不记录私密正文或凭据。

交付物：可复跑验收脚本、3 个任务的来源基准、脱敏运行轨迹和结果对照。

通过条件：3 个真实问题均有有效非空来源，答案的关键事实可追溯且不越过来源边界；上述隔离异常场景全部通过。配置 enabled=true、直接单测 hook 或零命中调用不能单独作为完成证据。

**KR-N3：让维护从诊断数字变成可执行动作。**

实施范围：

- 复核 11 个 Context 的用途，明确“周期维护/按需检查/停用”。默认保留个人五类的既有策略，历史 Daily 保持停用；项目、研究、联系人先按需，不为覆盖率强行全部启用。
- 通过已有 Ductor 维护入口跑通一次 maintain + tick 的完整周期，产生成功基线、来源版本和可恢复失败记录。成功表示过程完整，不表示所有待审核事实已经解决。
- 对 Markdown 索引与 Git 项目目录分别显示新鲜度。项目目录推荐每周检查或在明确使用项目证据前提示刷新，昂贵同步在维护路径执行。
- 将结构噪声、事实待核验、当前决策分层；默认每次展示 5–10 个有明确原因、来源和下一步动作的条目。完整计数与未展示项保留，不删除历史来源、不把截断或规则变化当成问题消解。
- 新增/仍未解决/已核实解决的比较基于完整、可比的状态。不能为让队列清零而伪造 reviewed_at、verified 或账户数据。

交付物：维护策略表、一次真实完整周期记录、项目目录新鲜度状态、面向日常使用的精简复盘输出。

通过条件：受控外部变化能在维护周期中被识别并进入索引/复盘；项目目录刷新有记录；失败、未配置和不完整状态可辨；用户每次看到少量可决定的行动，底层统计仍完整。测试仅使用隔离内容，真实待核验资历与持仓保持原有状态。

**KR-N4：只做一个可验收的知识更新闭环。**

实施范围：

- 以 research:ccs 现有 v2 页为试点，限定一个研究问题和 3–5 条主张，先复核范围、引用和发布依据。其余 Context 先保持稳定。
- 从已有真实资料或明确研究来源中选择支持、冲突、替代、无关四类材料，生成“受影响主张—依据—建议修改—仍未知”清单。不存在真实冲突时，该生产验收项保持未完成；可以用明确标注的隔离材料验证机制，不把合成冲突写入真实知识页。
- 沿用已有知识页/来源清单/版本机制生成局部草稿，不复制另一套事实数据库。机械来源更新受检处理，改变研究判断或解释真实冲突时由用户复核。
- 校验依据后发布下一版，保留旧版与变更理由。再由同一 Agent 读取该版本；页面缺失或过期时显式回退到实时来源，不把旧页默认为当前认识。

交付物：主张影响清单、受控更新草稿、带依据的新版本、旧版本及跨会话使用证据。

通过条件：该变的主张改变，未受影响部分稳定；冲突保留、无关来源不触发全页重写；过期草稿/中断可恢复；下一新会话能读到并使用新版本，且可展开到当前来源。单纯把 stale 改成 current 不算完成。

**KR-N5：第二批再接 Ownly。**

沿用里程碑 G 的已批准边界：复用现有只读 MCP 工具，首批对象详情/历史和近期续费；显式配置、只读工具白名单、超时与会话清理、参数/工具/查询时间及错误归一化。未配置时现有功能正常。返回结果只纳入本次 Context，不复制为 Markdown、不额外索引。按优先级排在核心批次之后；技术上只依赖 KR-N1 和现有 MCP 可连接，不把知识页发布或主张模型改造作为前置条件。主线等待宿主联调或事实复核时，可先做这个独立包；它仍是待办，不能因规划而标为交付。

**工作责任与验收记录。** 我负责实现、隔离测试、发布/恢复与诊断证据；用户只在需要确认新的研究判断、真实冲突解释或无法从来源确认的事实时参与。每包结果写回 EVALUATE.md，完成状态同步 TASKS.md；失败保留具体证据与下一步，不提前勾选。当前首个执行项为 KR-N1。

本批次先采用现有存储、宿主和 Context 机制。进一步减少全源读取、扩大图排名或引入向量检索，放到真实效果评测证明有收益之后评估。

## 2. 已完成

按主题列出，括号内为对应提交。

**解析与诊断的正确性**
- 单一链接解析器，供诊断与关系图共用，两者不可能给出不同结论。
- 解析规则对齐 Obsidian 官方文档（带路径按路径、裸名称按唯一文件名、再唯一别名），并做有界词法归一化
  （`../`、`./`）。`uncertain` 的情况只报告、不擅自判定。（`7d063f1`、`fe323e6`）
- 断链按出现位置给出 `triage_hint` 与原因，原始总数始终保留；`confidence` 恒为提示。

**复查议程的可信性**
- 复查 `basis` 为**语义基线**：Context 修订、定义指纹、诊断版本。任一变则拒绝比较，消失项不计作已解决。
- 不完整基线：返回 `incomplete`（顶层字段 + 警告行），**退出码 2**，且不会因为"有事项"而被掩盖。
- 显示截断（`--limit`、`--code`）只影响显示；台账、指纹、增量始终用全量。（`bd1187a`、`fe323e6`、`b8c3dec`）

**重复断链与孤立笔记**
- `contexts converge`：把重复断链收敛为"一个目标一次决策"（大小写不敏感），给出建议与证据；
  机器噪声默认排除但如实计数。（`72101c2`）
- 孤立笔记进入复查议程（`orphan_note`），范围与计数在**全量 occurrence 流**上判定，不从显示样本推断。

**派生卡片的可追踪性**
- 每张卡片登记真实输出路径、单 Context 指纹、`{来源: 校验和}` 与**编写依据**
  （`--expected-source-snapshot` 校验；未提供则标 `unverified basis`）。
- 登记读取区分 `absent / valid / unreadable / invalid`；登记损坏时 basis 不完整、不算已解决、退出 2。
- 卡片被外部修改会被标出。
- **未登记的卡片不会被静默信任**：登记机制之前写下的卡片都会报 `compiled_card_unregistered`，
  因为它的内容与编写依据都不在工具掌握之中；"修改时间比来源新"不构成它仍然有效的证据。

**知识页（P1）**
- `contexts page publish`：外部知识区、带版本、含依据 manifest。
- 强制区分**引用**与**推断**：引用必须指向真实笔记（记校验和），推断必须标注且无引用，
  `[conflict]` 至少两来源；引用不存在的笔记或越界行号**直接拒绝**；无标记条目拒绝。
- `contexts get`（按预算、放不下的主张省略并计数）、`contexts expand`（展开到当前来源，
  返回 `current/changed/missing`）。（`6ce95a1`）

**状态瘦身与性能**
- 历史 `bindings` 只保留最新版（855 KB → 232 KB）；索引去掉从未被查询的 trigram 表（102 MB → 51.8 MB）；
  schema 版本并入 generation 哈希，换版会重建而非复用。（`72101c2`）
- 一次 `review` 只读一次快照（原为两次）；无启用策略时不计算来源基线。
  实测：poll 14.09s → 0.03s，review 33.3s → 22.0s。（`f479337`）

**计划与文档**
- 路线图落为带验收条件的交付项（`TASKS.md`）；发布 3 份路径干净的复核/调研文档。（`ce3e956`、`02f68c7`）

## 3. 已确定的设计决策

这些是已经定下的，不是待选方案。改动需先改本节并说明原因。

1. **知识页是 Vault 外的派生物**。需要写进 Vault 时仍走 capture broker 的预览/提交。
   `append-create` 仅授权追加/创建；2026-10-23 按 ADR-001 增加独立授权的 `reviewed-edit`。
2. **全文修改有独立能力边界。** schema 3 的 `replace_existing` 计划包含完整 before/after、
   CAS 与恢复日志，只在 Windows 排他句柄下执行。部分写入拒绝盲目重试；它不承诺跨崩溃原子可见性。
   该原语没有附带自动 frontmatter 合并、别名改写、删除或搬移功能。
3. **工具不代写正文。** 生成物（卡片、知识页）的正文由调用方（agent 或人）撰写，工具只校验依据、控制范围、
   保存版本、解释变化。
4. **引用与推断必须可区分，且引用必须可核实。** 无法核实的引用与编造的引用无法区分，因此直接拒绝。
5. **不确定就不判定。** 歧义保持歧义、未定义回退只报告、孤立只提示。任何"计数依赖未定规则"的数字都是
   报告而非结论。
6. **不把派生摘要混入原始来源索引。** 否则总结会被当成独立证据再次引用。
7. **不引入向量库、常驻服务、独立记忆系统**，除非有实测瓶颈作为依据。
8. **发布绑定依据。** 每次发布记录其来源快照、Context 定义指纹与整理规则版本（诊断版本）。

## 5. 明确的非目标

- 不追求"把孤立笔记清零"。孤立信号用于**发现**内容，不是必须完成的待办。
- 不批量创建占位页来改善数字。占位页只提升链接可解析性，**不证明知识增长**；
  已创建的占位页标记 `stub: true`，应与成熟概念页区别对待。
- 不以命令数量、索引数量、诊断计数衡量进度。
- 不引入向量数据库、常驻服务、独立记忆系统作为前置条件。
- 不做未经实测收益的复杂度。

三类结果分别报告，不合并成一个"更好"的分数：

1. **结构已连接** —— 链接有落点（可解析性）。
2. **知识有内容** —— 页面有实际结论且来自独立来源。
3. **使用有帮助** —— 后续任务确实使用并减少错误或重复阅读。

## 6. 已知未验证或未证明的边界

诚实清单。以下都不是"已修好"，只是"目前这样处理"。

| 事项 | 边界 |
|---|---|
| `../`、`./` 路径解析 | 参考 Vault 中此类链接为 **0 条**，该修复只由合成测试证明，未改变真实库任何计数 |
| `[conflict]` 主张 | 真实库尚未发布（未找到经核实的来源冲突），该路径只由测试覆盖 |
| token 预算 | 是**估算**（CJK 字符计 1、其余计 1/4），不是分词器 |
| 卡片登记 | 只能覆盖它存在之后发布的卡；旧卡依赖默认路径 + mtime 回退 |
| `unverified basis` 卡 | 只被标出，不自动补正 |
| 性能数字 | 一台机器、一个 Vault、一次运行，非通用结论；`diagnose_vault` 未优化 |
| 歧义与未定义回退 | 仍然不判定；相关计数是报告而非结论 |
| 分类提示 | 是分流便利，不是完整性证明 |
| 竞品对比 | 调研文档中的星数与能力对比**未经本机复测**，应读作阅读清单 |
| 真实库语义正确性 | 未解析 6,251 处中约 89% 出自单个自动生成目录；这是分流结果，不等于修好了这些链接 |

## 8. 如何验证现状

全部命令均为只读（`--no-record` 可避免写台账）。把 `<NAME>` 换成本机登记的 Vault 名。

```bash
python scripts/knowledge_router.py doctor   --vault <NAME> --details --json
python scripts/knowledge_router.py contexts review   --vault <NAME> --no-record --json
python scripts/knowledge_router.py contexts converge --vault <NAME> --json
python scripts/knowledge_router.py contexts page list --vault <NAME>
python scripts/knowledge_router.py contexts get research:ccs --vault <NAME>
```

在参考 Vault 上应看到（与第 1 节一致）：

- `review`：事项 2,735；`counts_by_code` 为 `compiled_card_stale 1 / compiled_card_unregistered 1 / broken_reference 2255 / orphan_note 475 / ambiguous_reference 3`；
  `basis.complete=true`、`incomplete=false`；`card_registry_state=absent`；
  `maintenance_status=no_policies`、`maintenance_configured_contexts=0`。
- `converge`：`configured=true`、目标 146；建议分布 `create_or_relink 117 / needs_judgement 25 / check_naming_variant 4`。
- `page list`：两张页面均 `stale=False`。

测试：`python -m pytest`（274 项）与 `python -m ruff check scripts tests`。

**不要把"当前没有发现"读成"没有问题"**：`incomplete=true` 时结果不代表全部；`configured=false` 时不代表
范围为空；登记不可读时不代表没有卡片。
