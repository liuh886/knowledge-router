# 个人记录系统统一评审与实施（2026-10-25）

产品目标是同一份原始记录在不同任务中可找回、可引用、可复核，而非把多个领域的规则塞入一个万能 Agent。

| 层 | 责任 | 不承担 |
| --- | --- | --- |
| 输入入口 | idea/memo/todo/bio/milestone/invest 薄封装 | 文件拼接、证据判断、账务计算 |
| 应用 | memory_service 的类型格式、稳定ID、冻结意图 | 第二套任务数据库或事实库 |
| Broker | 策略、源哈希、锁、幂等、恢复凭据 | 判断交易真实、审核贡献 |
| 检索/Context | 引用原文、来源校验、维护范围 | 将命中内容自动认证为真 |
| 领域 | Biography 审核；Investment 流水及快照校验 | 与原始输入隐式双向同步 |
| 展示 | Persona、Dataview、简历 | 独立维护第二份事实 |

直接复用仓库中已经完成的 broker-backed memory_service，而非在安装目录再写一套系统。保留本机 todo_time 的日期解析，避免回退到把创建时间当排期的旧语义。注册五个明确 Context，继承原有定义；前三项按 capture 标签收录多年原始记录，两个领域按现有目录。维护显式触发，不增加后台任务。

每条捕获保存原文与 block ID。用户要求整理时，成果卡片/项目/正式记账引用原记录；多个主题共享链接，不复制多份。没有新的用户意图，不自动从 memo 生成 todo、不把投资观察转成交易、不把经历升为已核验资历。

Biography 的事实生命周期与核验状态分离。旧 10 张卡片的 verified 缺审核凭据，本轮保留历史说明改为 pending；修正 iCal 错误关联，收敛未经定位的强断言。原始证书逐项审查尚未完成，不能宣称 10 项资历均已认证。

统一维护队列复用同一次 source scan：结构检查报告缺来源、缺审核信息、无效数量/成本、重复标的、过期核验等。它不运行投资记账或论文审查。领域检查版本计入复盘比较 basis，规则变化不能被当成旧问题已经解决。

不选择新数据库或向量服务：当前问题是写入入口漂移和责任混淆，现有 Markdown、外部状态和 Context 已足够。后续先观察实际捕获、重试和复盘成本，再决定是否需要更复杂的自动化。

部署与验收结果见 EVALUATE.md。源码中已有未提交更改保留；不自动提交或推送。
