# 基础数据契约与治理边界

状态：2026-10-25 用户确认方向；第一批契约。本文规定语义与治理规则，不声称所有字段已由 API 返回或历史内容已经迁移。实现与缺口分别记录于 TASKS / EVALUATE。Markdown 和附件是来源；持久控制记录也需备份；索引、诊断和自动推导的角色提示可重建。

## 1. 职责

基础层负责准确读取、定位、引用、显式关系、结构约束、来源变更和受控修改。调用方负责总结研究、解释真实冲突、判断业务现状、制定行动和发布结论。可校验引用文件存在、行号与哈希，但不能因此宣称该文件支持某个论断或论断为真。

Context 仅作为可选、带版本的资料选择视图。没有 Context 的记录也必须能被检索和引用。保留现有 `research:ccs` 和已发布页，停止将其扩建作为基础层验收。Biography 审核与 Investment 记账的领域规则仍有效；底层可检查约束与审核字段，不能代替审核或成交核实。

## 2. 六类语义

| 维度 | 契约 | 已有能力与缺口 |
| --- | --- | --- |
| 身份 | 文件位置、文档身份、业务对象身份、版本、块引用分别表达。`(Vault, path)` 是定位，哈希是字节版本；业务 ID 的唯一范围由领域 schema 决定 | 索引 `ulid` 实为路径哈希，不能当作正文 ULID 或跨移动身份。已有 `ulid`、`id`、`^kr-...` 分别保留；不立即改索引或全库补 ID |
| 角色 | 原始输入、正文记录、参考材料、派生摘要、模板、历史副本、结构化应用记录采用不同检查规则 | 目录/type 仅提供 `role_hint`，不能认证身份、有效性或“主源”。未识别角色允许 unknown，不强制统一 type |
| 来源 | 区分记录原文、外部材料、导入、派生整理；保留已有 source_ref/evidence/来源链接和定位。来源存在不等于支持论断 | Evidence 已返回路径、行号、哈希；更细的来源语义依领域声明，缺失时标未知，不由 description 补造事实 |
| 时间 | 区分发生、记录、发布、编辑、有效期间、核验时间；保留精度与未知 | `created`/mtime 不自动解释为事件时间；`stale=false` 仅是相应来源校验结果，不是时效或真实性认证 |
| 引用 | 精确定位文件/块/章节/附件；缺失、歧义和不可读明确报告 | 共享链接解析器；诊断规则变更需升级版本。附件存在性不等于已读取其内容；OCR/图片解释另行请求，不编造转写 |
| 版本关系 | 保留明确的副本、快照、派生、替代关系和各自依据；重复 ID/相同字节仅是复核候选 | 不因同 ID 自动合并；备份可共享对象 ID。替代关系不自动删除旧记录，也不凭“较新”选出当前真值 |

跨系统使用身份时至少携带 Vault/业务命名空间；通用 `id` 不与 ULID 混为一谈。不同 schema/type 的同值不自动冲突，同一命名空间的同值也可能是合法快照。模板中的固定 ID 是候选问题，必须检查模板消费者后决定如何修改。

## 3. 最小治理，不引入全库表格负担

不要求每篇新增六套字段。优先读取现有 Frontmatter、正文和路径；仅在实际使用中补足必要的明确声明。`schema_version` 是业务格式版本，诊断规则版本另存，不能混用。

检查分为：

1. 确定的可读性/解析问题：编码失败、引用缺失、已复现解析误报。
2. 需要核对的身份/版本候选：同 ID 多路径、相同字节、副本与主源关系不明。
3. 领域审核事项：缺证据、未核实日期等；只列事项，不改变核验状态。
4. 允许保留的未知或合法差异：无 ULID、短正文、无链接、无周期维护本身不是错误。

计数必须区分目标数/出现次数、全部/显示项、完整/不完整。比较治理效果需要同规则、同范围、可比的来源基线；扫描期间文件变化时不得宣称固定快照。相同哈希只证明相同字节，不证明同一业务事实。

## 4. 第一批只读盘点

开发工具：`python scripts/data_inventory.py --vault-root <absolute-root> --limit 10`。
它复用安全读取与排除规则，读取两次比较 `(path, checksum)` 清单，仅输出 JSON 到 stdout，不创建目录、不写 Vault/注册表/索引、不运行笔记指令。调用方把 stdout 保存在 Vault 外。

盘点只提取顶层简单标量，不是 YAML 校验器；复杂字段、重复字段、未知格式显式披露，不能据此称元数据无效。ID 候选按字段及 schema/type 分组；角色仅是提示。Base64 计数仅表示载荷，不断言其可删除。缺失、空值和未解析值不自动补齐。

完整清单包含来源路径与 SHA-256；默认仅显示有限候选和少量三类样本，但总量完整。规则/格式版本随输出保存。第二次扫描一致只证明两次读取的清单一致，不承诺文件系统原子快照或之后未变化。

表格链接转义修复后的共享解析规则为 `RESOLUTION_VERSION=2`，诊断版本为 `3`。旧图投影缺少或不匹配解析规则版本时不复用：普通读取不使用其图权重，显式图查询可重建外部投影。来源相同不意味着不同解析规则产生的图可以混用。

2026-10-26：`quality.context_queue` 升为 schema 2 / membership_rules_version 2。归属复用 Context 的 scopes/include/exclude/tags 规则；聚合断链和歧义使用同一扫描中的完整问题出现记录，避免首个路径或 20 项来源样本决定整个目标的归属。同一相对链接在别处成功解析时不算本范围的问题。业务仓库路径不与 Vault 路径混用。

输出保留全部信号和显示截断，新增 membership_complete、context_source_counts、unverified_context_ids 与 membership_basis。所需标签不可读或来源列表不完整时，归属标为 incomplete，不把未知当作已排除；无标签筛选时仍可按可验证路径判断。该版本变化只影响 quality 归属，不声称 contexts review 同样存在缺陷，也不将队列重分类计为内容修复。

## 5. 三类试点与验收

| 样本 | 检查 | 允许产物 |
| --- | --- | --- |
| 原始捕获 | 原文、时间表达、已有块 ID、跨领域引用；不从 memo 推导任务 | 引用位置、保留未知、具体修订草稿 |
| 普通知识笔记 | 实际正文与说明是否一致、附件与引用、来源和日期含义 | 缺失载荷清单、明确的来源定位；不生成综合知识页 |
| 结构化应用记录 | 既有业务 ID/schema、字段含义、快照与备份、Frontmatter 事实 | 按领域规则的复核事项；不改金额/状态或重写业务 ID |

通过标准：原文可重读、引用能定位、缺失和未知可辨；应用对象不被当作空笔记；副本不被误删；源变化可见；只读运行前后没有由本工具产生的源写入。真实库仍在使用，外部并发变化要披露。

## 6. 修订路径

先冻结目标、原始哈希、原文恢复材料、修改后内容和理由；经过现有 broker 的对应策略执行并写后复核。保存策略保持不变。`append-create` 不允许替换旧文；受限时提交具体草稿与待办，不通过 shell 绕过，也不为此提升保存策略。新建治理入口可在既有目录中经 broker 排他创建。全量清单、恢复材料存 Vault 外，库内只保留一份人可读治理入口。
