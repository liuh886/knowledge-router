## 3. 本轮仍复现的缺口

以下均使用隔离临时目录与合成笔记，不修改真实 Vault。

### P1：Context 范围变化仍产生假消解

位置：[context_review.py](../scripts/context_review.py:305)、[比较逻辑](../scripts/context_review.py:335)。

复现：Context 原本覆盖 Area，存在两个断链；保持所有笔记内容不变，只将该 Context 修订为覆盖 Other。新旧扫描都完整，结果仍为 `comparable=true`，并报告 **2 个 resolved item**。

原因：basis 记录扫描完整性，却未记录/比较 Context 定义身份、过滤范围和诊断规则版本。离开观察范围不等于已修复。

建议：加入语义比较基线（定义/范围指纹、解析器与诊断版本），范围变更报告“移出范围/基线重建”，不能自动确认消解。新增“改 scopes/exclude/tags 但不改原文”的回归。

### P1：不完整 review 的 CLI 仍成功退出

位置：[knowledge_router.py](../scripts/knowledge_router.py:795)。

复现：一个正常注册的 Context 加一个不可解码的来源，CLI 返回 `status=incomplete`、`scan_incomplete=true`、零事项，但 **exit code=0**。

影响：只依据退出码运行的调度器会认为该次检查正常完成。JSON 的修复尚未贯通命令行契约。

建议：以完整性决定失败退出码（与 tick/coverage 一致）；有部分事项但扫描不完整时也要明确表示不完整，不能仅靠顶层 attention 掩盖。补 CLI 级断言。

### P1：父目录相对路径仍无法解析

位置：[link_resolver.py](../scripts/link_resolver.py:262)。

复现：`Area/Sub/Source.md` 链接 `[[../Target]]`，真实文件为 `Area/Target.md`，仍被判为 `unresolved`。`PurePosixPath(parent, target)` 保留 `..`，与索引中的正规路径不一致；这不是同名歧义。

建议：对 Vault 相对路径做受边界约束的词法归一化，处理 `.`/`..`，拒绝越出 Vault；显式相对标记应保留到解析阶段，避免被错误降为裸文件名。补父目录、同目录显式路径、根路径冲突和附件用例。

### P1：自定义外部卡片路径仍漏检

位置：[context_review.py](../scripts/context_review.py:119)。

复现：通过真实保存函数分别写默认 `vault_compiled/A.md` 和自定义 `custom_cards/Different.md`，两份均早于来源。review 仅识别默认卡片。

原因：目前仍在猜测默认目录/文件名，没有登记 `--out-root` / `--name` 的实际输出，也没有保存来源依赖哈希。

建议：最小化增加外部卡片登记及来源依赖信息，覆盖自定义路径、来源删除和定义变化；不能将当前实现称作“全部外部卡片更新检测完成”。
